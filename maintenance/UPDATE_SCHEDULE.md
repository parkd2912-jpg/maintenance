# 자동 유지보수 업데이트 — 주간 예약표

> 작성: 2026-11-21. 이 파일은 **배포Slott 운영표**다. `feedback-token.txt` 와 달리 민감정보가 없으므로 커밋해도 된다.

## 운영 규칙 (사용자 확정)

1. **배포는 주 1회(토요일 04:00).** 슬롯은 미리 한 주씩 예약해 둔다.
2. 내가 수시로 알려주는 변경사항은 **관련 조치끼리 같은 주 슬롯에 묶는다.**
   - 예: "표시/라벨 개선" 계열은 한 슬롯, "초보자 안내" 계열은 한 슬롯.
3. **묶을 만한 기존 슬롯이 없으면 이미 예약된 그 다음 주 슬롯에 넣는다.** (새 슬롯을 임의로 만들지 않음)
4. **만료 없는 피드백 토큰은 1개월 뒤(2026-12-21) 업데이트 항목에 함께 묶어 배포한다.**
   - 만료일이 있는 토큰은 넣지 않는다.
5. 버전 번호는 슬롯 순서대로 1개씩 올린다. 현재 최신 배포: **v1.16.0** (2026-11-21 우선처리 조기 배포 6건).
   - 예외: 2026-11-21 에 "보고서 자동 업로드 + 피드백 안내 + 뉴비 보고서"가 최우선 요청으로 들어와 주간 슬롯을 기다리지 않고 **v1.14.7 로 즉시 배포**함.
   - 같은 날 "A 선택 후 예약 실행도 자동 업로드 + 업로드 원본 버그" 추가 요청으로 **v1.14.8 로 즉시 배포**함. 이후 슬롯 번호가 밀림.
   - 같은 날 "조사 결과 우선 반영 — 업데이트 실패 이력/오류 코드 해석(보고만)" 요청으로 **v1.15.0(기능 추가 = MINOR) 즉시 배포**함.
   - 같은 날 "예약 배포 1주 전 미리검증" 요청으로 **v1.15.1(동작 변경 = MINOR) 즉시 배포**함.
   - 같은 날 "피드백 개인정보 범위·다음 버전 수정 안내" 요청으로 **v1.15.2(문구 수정 = PATCH) 즉시 배포**함.
   - 같은 날 "Ulanzi 버튼용 버전 안내" 요청으로 **v1.16.0(기능 추가 = MINOR) 즉시 배포**함. W1~W4 버전도 1.16.1~1.16.4 로 함께 밀림.
6. 실제 PC 반영은 예약 작업이 수행한다.
   - `OpenCode-Maintenance-AutoUpdate-Weekly` : 매주 토 04:00 (첫 실행 11/28) — **안정본만** 설치
   - `OpenCode-Maintenance-AutoUpdate-1Month` : 12/21 04:00 (토큰 포함)
   - `OpenCode-Maintenance-PreVerify` : **매일 03:30** — RC 가 있을 때만 미리검증(보고만, 설치본 변경 없음)

## 3단계 검증 배포 게이트 (2026-11-21 사용자 확정)

예약일을 **D** 라고 할 때, 한 버전은 아래 3단계를 반드시 거친다.

| 단계 | 시점 | 무엇을 하느냐 | 산출물 |
|---|---|---|---|
| ① 로컬 카나리 | **D-14** | 빌드한 ZIP 을 **이 PC 에 로컬로 먼저 설치**해 실제 점검을 돌려본다. 문제가 있으면 이 단계에서 고친다. | 이 PC 설치 + 점검 결과 |
| ② RC 공개·미리검증 | **D-7** | 같은 ZIP 을 GitHub 에 `vX.Y.Z-rcN` **prerelease** 로 공개. `OpenCode-Maintenance-PreVerify`(매일 03:30)가 파일/구문/BOM/VERSION/회귀 SelfTest 를 검사. 사용자는 안내창 아래 **미리 해보기**로 별도 폴더에서 체험 가능. | 바탕화면 `자동유지보수_미리검증결과.txt`, `H:\AutoMaintenance_PreVerify.log` |
| ③ 본배포 | **D (토 04:00)** | 같은 ZIP 을 **안정 태그 `vX.Y.Z`** 로 새로 공개 → 주간 자동업데이트가 설치. RC(`vX.Y.Z-rcN`)는 prerelease 로 남겨 두어 자동업데이트가 계속 무시. 12/21 토큰분은 M1 슬롯에 함께. | 안정 설치 + `배포됨` 갱신 |

- **RC 는 절대 자동 설치되지 않는다.** `vX.Y.Z-rcN` 은 `[version]` 파서가 무시하고 `prerelease=true` 도 한 번 더 걸러낸다.
- **미리 해보기는 현재 설치본을 안 바꾼다.** `H:\AutoMaintenance_Canary_<태그>` 에만 설치하고 바탕화면에 `자동유지보수 미리해보기.lnk` 를 만든다. 예약 작업·메인 바로가기는 그대로.
- **미리검증은 읽기 전용이다.** 삭제·수정·업로드 없이 결과만 보고한다. 문제가 나면 RC 를 고쳐 다시 올리고, 그 슬롯의 본배포를 미룬다.
- **검증 통과 문구**: "문제 없음 — 예약일 본배포 진행 가능" / 실패 시 "문제 발견 — N건 (본배포 보류)" + 항목별 상세.

### 릴리스 노트 문구 규칙 (안내창이 그대로 읽어감)

릴리스 노트의 `-` 목록이 안내창의 "기능 n가지" 목록이 된다. 채널별 첫 문구를 아래처럼 쓴다.

- **② RC(prerelease)** — `미리 다운로드 / 미리 해보기`
  ```
  미리 해보기 — 준비 중인 기능입니다.
  - 전 버전보다 N가지 기능이 추가되고, 추가된 기능은 아래와 같습니다.
  - (문제가 있으면 제작자에게 연락 주세요. 최소 로컬 컴퓨터로 검증 완료.)
  - ...실제 변경 항목...
  ```
- **③ 안정본(stable)** — `현 버전 다운로드`
  ```
  현 버전 다운로드 — 안정화된 기능입니다.
  - 추가된 기능 설명: ...
  - ...실제 변경 항목...
  ```

## 컴퓨터 초보자를 위한 기능 업데이트 내용

이번 예약은 **실제 점검 결과와 자주 들어온 문의**를 바탕으로, 컴퓨터를 잘 모르는 분도 안전하게 쓸 수 있도록 정했습니다.

- **v1.15.0 — 업데이트 실패 이유를 알려줘요**: 윈도우가 업데이트에 실패하며 남긴 메모를 최근 30일치 읽어, `0x80070002` 같은 숫자 코드가 무슨 뜻인지 쉬운 말로 알려줍니다. 예를 들어 "필요한 파일을 못 찾았어요", "드라이버 때문에 멈췄어요"처럼 말이에요. **자동으로 고치지는 않고 알려주기만 합니다.** 계속 실패하면 설정 > Windows Update > 업데이트 기록에서 직접 확인하실 수 있어요.
- **v1.15.1 — 새 기능을 미리 해볼 수 있어요**: 정식 배포 일주일 전에 "준비 중인 기능"을 먼저 알려드립니다. 안내창 아래의 작은 **미리 해보기** 버튼을 누르면 지금 쓰고 있는 버전은 그대로 두고 새 기능만 따로 받아 체험할 수 있습니다. 문제가 있으면 제작자에게 연락 주세요. 매일 자동으로 미리 검사해서 결과를 바탕화면 `자동유지보수_미리검증결과.txt` 에 적어둡니다. 정식 버전은 예약된 날에만 자동으로 설치됩니다.
- **v1.15.2 — 피드백 보낼 때 알려드려요**: 오류 확인을 위해 올라가는 내 컴퓨터 정보는 CPU 모델과 GPU 모델뿐입니다. 이름·경로·시리얼·IP 같은 개인정보는 자동으로 지우고, 보고서 구분용 해시 앞 6자리만 함께 올라갑니다. 보내주신 문제는 대부분 다음 버전에서 수정됩니다.
- **v1.16.0 — 버튼 하나 더 만들었어요**: 조회/다운/보고 옆에 **버전** 버튼을 추가합니다. 버튼 화면에는 현재 버전, 다음 예약 버전, 예약된 버전 수가 뜨고, 누르면 현재 버전 기능과 다음 버전에 추가·변경되는 기능이 메모장에 정리돼 나옵니다.
- **살펴본 자료**: 실제로 올라온 점검 보고서 2건(RTX 5060 Ti / RTX 5070 Ti)과 내 PC 점검 결과. 두 보고서 모두 부팅 보안 인증서 갱신 미완료, 재부팅 대기, 오래된 드라이버 다수 보류가 반복됐습니다. 내 PC에서는 업데이트 상태 메모를 점검 결과로 잘못 읽던 문제가 있었고, v1.14.8 에서 고쳤습니다.
- **W1 — 결과 화면이 헷갈리지 않게**: 가상 디스플레이가 오류처럼 보이던 표시를 실제 GPU와 구분해 알려줍니다. 하드웨어 오류(WHEA Event 18)가 나올 때도 "재부팅 후 다시 확인"과 BIOS·칩셋 드라이버 점검을 함께 안내해, 초보자가 원인을 찾기 쉽게 합니다.
- **W2 — 부팅 보안과 백신 알림이 이해되게**: Windows 부팅 보안 인증서가 2026년에 바뀌는 시점에 맞춰, 갱신이 안 됐을 때 생길 수 있는 문제를 미리 알려줍니다. 재부팅이 필요하면 "재부팅 후 다시 확인"이라고 정확히 알립니다. 또한 백신의 '제어된 폴더 접근'이 게임이나 정상 프로그램을 가끔 차단하는데, **지금 켜져 있는지만 알려주고 자동으로 바꾸지는 않습니다.**
- **W3 — 드라이버·디스크 관리가 쉬워지게**: 오래된 드라이버가 계속 남아 있는 이유와 정리 방법을 쉽게 알려줍니다. 드라이버를 바꾸기 전 백업하는 방법도 함께 안내합니다. 디스크가 자주 100%로 올라가는 이유(검색 인덱싱·오래된 디스크·시작 프로그램)도 결과표에 연결해 설명합니다. 삭제는 여전히 **직접 확인 후에만** 진행합니다.
- **W4 — 오래된 Windows를 안전하게 안내**: Windows 10은 2025년에, 7·8.1은 그보다 훨씬 전에 지원이 끝났습니다. 지원이 끝난 Windows는 보안 업데이트가 오지 않는다는 점을 초보자용 말로 알려줍니다. 새 Windows(26H2)로 올라갈 때 알려진 문제가 있으면 함께 안내합니다.
- **자주 들어온 문의 정리**: ①느린 부팅·디스크 100% ②드라이버와 백업 ③업데이트 실패 ④백신 오탐 ⑤노트북 배터리 마모 순이었습니다. 이 중 ①·②·④·⑤는 이미 구현했거나 위 슬롯에 담았고, ③은 DISM/RestoreHealth 로 복구는 하고 있었지만 "왜 실패했는지"는 알려주지 못했습니다. v1.15.0 에서 최근 30일 실패 기록과 오류 코드 뜻을 쉬운 말로 보여주도록 보완했습니다(고치지는 않고 읽기만 함).
- **이미 들어가 있어서 새로 넣지 않은 것**: 시스템 파일 검사, 메모리 진단, 디스크 상태 검사, **노트북 배터리 닳은 정도**, **백신 실시간 보호와 서명 최신 여부**, **복원 지점 자동 생성**, **시작 프로그램 목록**, **시간 자동 맞춤**, **디스크 여유 공간 부족 경고**, 네트워크 확인, 개인정보 가리기, 초보자용 결과표. 초보자가 필요로 하는 기능 상당수가 이미 들어가 있습니다.

## 작업 순서 (매주 — 3단계 게이트 적용)

1. 사용자에게 받은 항목을 위 분류 기준으로 분류 → 해당 슬롯에 추가 (없으면 다음 빈 슬롯).
2. **D-14 (로컬 카나리)**: 그 슬롯 항목만 구현 → VERSION 올림 → 파서/BOM/SelfTest 검증 → 로컬 ZIP 빌드 → **이 PC 에 로컬 설치해 실제 점검**. 문제 나면 여기서 고친다.
3. **D-7 (RC 공개)**: 같은 ZIP 을 `vX.Y.Z-rcN` prerelease 로 Release. 릴리스 노트는 위 "릴리스 노트 문구 규칙" 적용. 매일 03:30 미리검증 로그·바탕화면 보고서 확인. 원하면 **미리 해보기**로 별도 폴더에서 체험.
4. **D일 (토 04:00, 본배포)**: 미리검증이 "문제 없음"이면 같은 ZIP 을 안정 태그 `vX.Y.Z` 로 공개 → 주간 자동업데이트가 설치. RC 는 그대로 남아도 `[version]` 파서가 무시하므로 자동 설치되지 않는다. 문제가 나면 본배포를 미루고 RC 를 고쳐 다시 올린다.
5. 본배포 후 이 표 상태를 `배포됨` 으로 갱신.
6. 12/21 M1 에는 토큰이 만료 없는지 다시 확인한 뒤 함께 배포.
